# Decision Log Template

| Field | Description |
|---|---|
| Decision | What was decided, in one sentence |
| Date | When the decision was made |
| Owner | Who made or is accountable for the decision |
| Evidence | What data or input informed it |
| Alternatives considered | What else was on the table |
| Tradeoff accepted | What was deliberately given up |
| Assumptions | What has to remain true for this decision to hold |
| Revisit trigger | What would cause this decision to be reopened |

## Why Log Decisions Instead of Just Outcomes

Six months later, nobody remembers *why* a decision was made — only that it was. A decision log turns institutional memory into a searchable record, which matters most when someone asks "why didn't we just do X instead," and the honest answer should be retrievable, not reconstructed from memory.

## Example Entry

| Field | Entry |
|---|---|
| Decision | Use a tiered risk-review process instead of reviewing every AI use case the same way |
| Date | Sample date |
| Owner | AI Program Lead |
| Evidence | Intake backlog data showing low-risk use cases waiting as long as high-risk ones |
| Alternatives considered | Review everything uniformly; review nothing without a full business case |
| Tradeoff accepted | Some scrutiny reduction on low-risk use cases, in exchange for faster overall throughput |
| Assumptions | Risk self-assessment at intake is reasonably accurate |
| Revisit trigger | A low-risk use case causes an incident, indicating the self-assessment step needs tightening |
