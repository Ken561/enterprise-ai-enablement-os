# AI Use-Case Intake Form

> *Portfolio template informed by enterprise AI program-management experience.*

## Purpose

Capture enough information at submission to triage risk and prioritize the request — without requiring a full business case before anyone knows if the idea is worth pursuing.

## Fields

| Field | Description |
|---|---|
| Use-case name | Short, descriptive title |
| Business problem | What problem does this solve, in one or two sentences? |
| Target users | Who will use this, and how many? |
| Expected value | What outcome improves, and roughly by how much? |
| Data involved | What data does the use case touch? |
| Risk level (self-assessed) | Low / Medium / High, per the [Risk Decision Tree](../governance/decision-tree.md) |
| Existing alternatives | How is this problem solved today? |
| Dependencies | What systems, teams, or approvals does this depend on? |
| Requested timeline | When does the requester need this live? |
| Sponsor | Who owns this from the business side? |
| Success metric | How will you know this worked? |

## Example (Portfolio Sample Data)

| Field | Example Entry |
|---|---|
| Use-case name | Engineering Issue Capture Assistant |
| Business problem | Engineers spend time manually structuring bug reports before they can be triaged |
| Target users | ~150 engineers across two teams |
| Expected value | Reduce time-to-triage; improve report completeness |
| Data involved | Internal issue text, no customer or personal data |
| Risk level (self-assessed) | Low |
| Existing alternatives | Manual issue templates, inconsistent completion |
| Dependencies | Issue tracker API access |
| Requested timeline | Next quarter |
| Sponsor | Engineering Manager |
